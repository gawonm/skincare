> [Hybrid48](2026-09-27_NIA_CASE_HYBRID_RERANKER_TOP3_FINAL_REPORT.md)과
> [동일 후보 수 Hybrid40](2026-09-27_NIA_CASE_HYBRID40_TOP3_REPORT.md) 모두
> Dense40보다 nDCG@3이 낮았다. 현재 Case 경로는 Dense40을 유지한다.

## 평가 조건

- 코퍼스: NIA Case 3,581건
- 질의: 기존 개발·회귀셋 24건의 원문
- Dense 후보: 기존 BGE-M3 Top-40 실행 결과를 그대로 재사용
- BM25-new: NIA Case 질문 필드만 사용하고 일반 표현을 제외한 단어·한글 2글자 토큰 사용
- 지표: 골든셋 v5에 판정된 관련 Case 기준 qrel Recall
- 기존 질문+답변 BM25 RRF 재현: 24/24 질의의 Top-40 일치

## 실제 데이터에서 확인된 점

- 기존 동일 가중치 RRF는 Dense 후보를 평균 24.2/40건만 보존했고, 판정된 관련 후보 7건을 탈락시켰다.
- 질문 전용 BM25 RRF는 qrel Recall이 0.690로 조금 높았지만 관련 후보 7건이 여전히 탈락했다. 질문 필드 전환만으로는 교체 손실을 해결하지 못한다.
- `dense_36_question_4`와 `dense_32_question_8`은 총 40개를 유지하면서 Dense 앞부분을 고정하고 BM25 신규 후보로 꼬리를 교체한다.
- `dense_40_question_4`와 `dense_40_question_8`은 Dense 40개를 모두 보존하고 BM25 신규 후보만 추가한다.
- Dense 40개와 질문 BM25 신규 8개를 합친 안은 qrel Recall 0.720, 9개 질의 개선, 0개 질의 하락이었다. 판정된 Grade-3 후보는 11건 추가되고 탈락은 0건이었다.

## 잠정 설계안

1. 단일 턴 Case 검색은 자유형 LLM 재작성을 사용하지 않고 사용자 원문을 유지한다.
2. 상품 개수·구매 조건·루틴 일정처럼 Case 검색과 무관한 실행 지시만 결정적으로 제거한다.
3. BGE-M3 Dense Top-40을 모두 보존한다.
4. NIA 질문 필드 BM25에서 Dense와 중복되지 않는 상위 8건을 추가해 최대 48건을 만든다.
5. 동일한 원문 질의와 동일한 BGE reranker로 Dense40과 Hybrid48의 최종 Top-3를 비교한다.
6. Hybrid48이 Top-3 품질을 개선하고 지연 증가가 허용 범위일 때만 운영 경로로 채택한다.

## Query Rewriting 적용 범위

- 현재 24건에서 자유형 재작성은 Dense qrel Recall을 0.648에서 0.617로 낮추고 평균 0.964초를 추가했으므로 단일 턴 기본값으로 채택하지 않는다.
- 멀티턴의 생략된 대상·피부 상태 복원은 목적이 다르므로 별도 멀티턴 평가셋에서 검증한 뒤 제한적으로 적용한다.
- 복합 고민 축 분리는 기존 naive multi-query 회귀와 같은 위험이 있다. Dense 원문 후보를 보존하는 별도 실험 전에는 Hybrid48에 섞지 않는다.

## 해석 제한

- 후보 수가 44·48인 전략은 Top-40과 계산량이 다르므로 Recall 수치를 직접 우열로 단정하지 않고 리랭커 입력 후보 확장안으로 본다.
- 이 평가는 후보 단계다. 최종 채택에는 동일 BGE reranker 이후 Top-3 품질과 지연 시간을 비교해야 한다.
- v5 qrel은 원문 질의의 Dense·lexical·metadata 후보 풀을 판정해 만들었다. 따라서 lexical 전략은 판정 커버리지가 상대적으로 좋을 수 있으며 미판정 신규 후보의 관련성은 이 수치에 반영되지 않는다.
- 24건은 반복 사용한 개발·회귀셋이며 전체 코퍼스 recall이나 독립 일반화 성능이 아니다.
