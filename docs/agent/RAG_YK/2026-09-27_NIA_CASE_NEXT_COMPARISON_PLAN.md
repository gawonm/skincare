# NIA Case 검색 방식의 다음 비교 실험 계획

> 범위: Case 후보 검색과 Top-3 재정렬. Evidence RAG, 제품 추천, DB 스키마 및 운영 경로 변경은 포함하지 않는다.
> 상태: 1차 동일 후보 수 비교 완료. 결과는 [Hybrid40 Top-3 보고서](2026-09-27_NIA_CASE_HYBRID40_TOP3_REPORT.md)를 기준으로 본다.

## 실행 결과와 결정

24개 기존 개발·회귀 질의에서 Hybrid40의 판정된 관련 후보 Recall@40은 0.648→0.683으로 올랐다. 그러나 같은 BGE 재정렬 후 nDCG@3은 0.733→0.682, P@3은 0.792→0.764, Hit@3은 0.917→0.875로 낮아졌다. Grade-3 Hit@3은 0.708로 같았다. nDCG@3은 Hybrid 개선 0건·하락 5건·동일 19건이었다.

따라서 아래 1차 선택 기준에 따라 **Dense40을 유지한다.** 복합 질의 12건에 대한 Hybrid40 확장 평가는 이번에는 실행하지 않는다. 새 3건은 현재 Codex 세션이 판정하고 앞선 3건은 기존 Codex 판정을 재사용했다. 평가자는 변경된 순위를 봤으므로 이 결과를 완전 블라인드 판정으로 표현하지 않는다.

## 1. 비교 전에 확인한 사실

- 현 기준선은 원문 질의 → BGE-M3 Dense Top-40 → `bge-reranker-v2-m3` Top-3이다.
- Dense 후보의 임베딩 원문에는 NIA 질문·답변·추론이 들어 있다. 현재 재정렬 입력에는 질문·답변과 `target_concern`, `skin_concerns`, 피부 타입, 나이, 성별이 들어간다. 따라서 메타데이터를 처음 추가하는 실험으로 설명하면 안 된다.
- 질문 전용 BM25는 과거 NIA 사례의 `question` 필드에서 어휘 후보를 찾는다. 사용자의 입력 질의와 별개의 필드다.
- 기존 24질의에서 Dense40의 판정된 관련 후보 Recall은 0.648, Dense36+질문 BM25 신규 4건의 Recall은 0.683이었다. 후자는 후보 단계에서 7질의 개선·1질의 하락·16질의 동일이었다. 이 후보 결과를 바탕으로 위의 Top-3 비교를 실행했다.
- Dense40+질문 BM25 신규 8건인 Hybrid48은 후보 Recall을 0.720으로 올렸지만, 공통 BGE 재정렬 뒤 nDCG@3은 0.733→0.701, P@3은 0.792→0.778로 낮아졌다. 평균 재정렬 시간도 4.720초→5.433초로 늘었다.
- 앞서 제안한 답변 필드 가중치 0.2 및 추가 메타데이터 점수는 측정된 최적값이 아니다. 다음 1차 실험에 넣지 않는다.

## 2. 실행한 동일 후보 수 비교

| 조건 | 후보 구성 | 공통 조건 |
| --- | --- | --- |
| A: 현재 Dense40 | BGE-M3 상위 40건 | 사용자 원문 질의, 동일 NIA 코퍼스와 BGE 재정렬기 |
| B: Hybrid40 | BGE-M3 상위 36건 + 이 36건에 없는 NIA 질문 필드 BM25 후보 4건 | 총 40건, 동일 사용자 질의와 재정렬기 |

BM25 후보가 Dense36에 이미 있으면 중복을 건너뛰고 다음 BM25 사례를 가져온다. BM25 후보가 원래 Dense 37~40위와 겹칠 수 있다. 필요한 후보가 부족하면 Dense 꼬리에서 채운다. 기존 평가 파일에는 두 조건의 후보 ID가 저장돼 있으므로, 1차 비교에서는 임베딩·DB 검색을 다시 실행할 필요가 없다.

1. 저장된 두 후보 목록을 동일한 Case 본문·메타데이터 DTO로 복원한다.
2. 동일한 BGE 재정렬기, 질문·답변 입력 형식, 중복 처리, `CareContext` 조건으로 각각 Top-3를 만든다. 이번 방법 비교에서는 두 조건 모두 빈 `CareContext`를 사용해 필터 효과를 분리한다.
3. 기존 qrel에 없는 Top-3 사례가 생기면 질의와 NIA 질문·답변을 읽고, 검색 조건명과 순위를 가린 상태에서 현재 Codex 세션이 기존 0~3 관련도 기준으로 판정한다. 판정 이유와 대상 Case ID를 보존한다.
4. 두 조건을 같은 확장 qrel로 다시 계산한다. 한쪽에만 새 판정을 더한 서로 다른 분모의 평균은 비교하지 않는다.

### 보고할 지표

| 지표 | 역할 |
| --- | --- |
| 판정된 관련 후보 Recall@40 | 1차 후보에서 관련 사례를 얼마나 살렸는지 보여주는 보조 지표. 전체 3,581건의 완전 Recall은 아니다. |
| **nDCG@3** | 최종 Top-3의 관련도 등급과 순서를 함께 반영하는 1차 선택 지표. |
| P@3, Hit@3, Grade-3 Hit@3 | 관련 사례의 슬롯 수, 최소 한 건의 포함 여부, 강한 관련 사례 포함 여부를 분리한다. |
| 질의별 개선·하락·동률 및 바뀐 Case ID | 평균이 특정 질의의 손실을 가리지 않도록 한다. |
| BM25 조회 시간, BGE 재정렬 시간 | 같은 후보 수에서 추가 조회 비용과 최종 대기 시간을 따로 본다. 오프라인 색인 구축 시간은 별도로 기록한다. |

**선택 기준:** Hybrid40이 nDCG@3을 높이면서 P@3·Grade-3 Hit@3의 뚜렷한 하락이나 특정 회복 우선 질의의 큰 악화를 만들지 않을 때만 다음 검증으로 넘긴다. 후보 Recall 상승만으로 채택하지 않는다. 24건은 반복 사용한 개발·회귀셋이므로 차이가 작으면 Dense40을 유지한다.

## 3. 1차 결과가 좋을 때만 복합 질의 확인

기존 신규 복합 질의 12건을 사용한다. 이 세트는 현재 자극·회복 우선 요청 9건과 대조 질의 3건을 포함하지만, 앞선 오류 유형을 보고 만든 합성 도전셋이다.

- A/B에서 질의와 후보 수를 같게 유지하고, 동일한 실제 `CareContext`를 적용한다.
- 새 Top-3 중 기존 49건 판정에 없는 사례만 같은 기준으로 추가 판정한다. 관련도 0~3과 관리 방향 `aligned/conflict`를 별도로 기록한다.
- 관련 Hit@3, Grade-3 Hit@3, **관리 방향 부합 사례가 하나 이상 있는 질의 수**, 충돌 사례 노출 슬롯, 빈 결과 질의 수를 함께 보고한다.
- Hybrid가 관련 사례를 늘리더라도 회복 우선 질의에서 충돌 노출이나 빈 결과가 늘면 운영 채택을 보류한다.

## 4. 결과가 나쁘면 무엇을 할 것인가

Dense40을 유지하고, Hybrid가 새로 올린 사례 중 **질문 표현은 닮았지만 답변의 관리 방향이 어긋난 사례**를 추적한다. 이 실패가 반복될 때만 질문·답변 필드를 분리한 BM25 점수나 명시적 고민 메타데이터의 후보 단계 활용을 다음 실험으로 설계한다. 필드 가중치와 메타데이터 가중치를 한 번에 바꾸면 어느 신호가 성능을 바꿨는지 알기 어렵다. 답변 가중치 `0.2` 같은 값은 사전에 정한 후보값일 수는 있지만 현재 데이터가 뒷받침하는 최적값으로 제시하지 않는다.

자유형 LLM 질의 재작성은 이미 같은 24건에서 Dense 후보 Recall을 0.648→0.617로 낮췄으므로 이번 검색 방식 비교에는 섞지 않는다. 실제 워크플로우의 `gpt-4o-mini` 의도 해석은 별도 API 실행으로 확인됐다. 이번 A/B는 Case 검색과 재정렬을 통제한 실험이며 OpenAI API 판정 호출은 필요하지 않다.

## 5. 발표에 사용할 결론의 범위

- 현재 확정 가능: Dense40, 기존 RRF40, Hybrid48의 후보·Top-3 비교와 자유형 재작성 실험 결과.
- 이번 실행으로 추가: **동일한 40건 예산에서** Dense40과 Hybrid40의 후보 회수와 최종 Top-3 품질 비교. 재정렬 시간은 기록했지만, BM25 조회와 실제 DB 요청을 포함한 전체 지연은 측정하지 않았다.
- 복합 12건 확인 뒤 추가 가능: 합성 자극·복합 질문에서의 관련성과 관리 방향 노출 비교.
- 이 개발·도전셋 결과를 실제 사용자 분포의 일반화 성능이나 전체 답변 품질로 표현하지 않는다. Case가 최종 답변에 기여하는지는 같은 실제 LLM과 지시문으로 Case 입력만 바꾼 별도 응답 A/B가 필요하다.
