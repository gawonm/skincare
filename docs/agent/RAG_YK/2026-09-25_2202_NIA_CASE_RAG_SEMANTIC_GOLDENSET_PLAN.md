# NIA Case RAG 의미 검색 골든셋 및 고정 환경 성능평가 계획

> 작성 시각: 2026-09-25 22:02 KST
>
> 상태: **기존 임상 기준 혼합 v1 평가 완료, NIA 코퍼스 상대 검색 관련성 v2 전환 시작**
>
> 범위: **Agent 파트의 NIA Case 검색·후보 선별·BGE 리랭크 평가만 포함**

## 문서 운영 원칙

이 문서는 현재 결론만 남기고 이전 판단을 덮어쓰는 문서가 아니라, 결정이 바뀐 이유까지 추적하는
계획·작업 기록이다.

- 상단 본문에는 현재 유효한 평가 설계를 적는다.
- 이전 안이 바뀌면 내용을 삭제하지 않고 작업 기록에 초기안·변경 이유·대체 결정을 남긴다.
- 더 이상 유효하지 않은 수치나 방식은 `폐기` 또는 `대체됨`으로 명시한다.
- 실제 측정 결과가 나오면 사전에 정한 기준과 사후 해석을 구분해 기록한다.
- 골든셋 판정이 수정되면 기존 버전, 수정 사유, 영향받은 질의를 남긴다.

## 1. 목적

이번 작업의 목적은 새로운 검색 방식을 개발하거나 여러 모델을 비교하는 것이 아니다. 현재 운영
후보인 다음 구성을 고정하고, 실제 사용자형 질의에서 추천에 유용한 NIA Case를 충분히 회수하고
상위에 배치하는지 평가한다.

```text
사용자 질의
  → BGE-M3 단일 임베딩 검색 Top-40
  → 고민 메타데이터 기반 최대 20건 선별
  → bge-reranker-v2-m3 Top-3
```

평가가 답해야 하는 질문은 다음 세 가지다.

1. 추천에 유용한 Case가 최초 Top-40에 들어오는가?
2. Top-20 선별 과정이 좋은 후보를 제거하지 않는가?
3. BGE 리랭커가 가장 유용한 Case를 Top-3에 배치하는가?

성분 추천 기준은 별도 추천 시스템의 성능을 평가하기 위한 정답이 아니다. 사용자에게 어떤 Case가
실제로 유용한지 판정하기 위한 외부 기준으로만 사용한다.

## 2. 고정 평가 환경

평가가 끝날 때까지 다음 조건을 변경하지 않는다.

| 항목 | 고정값 |
| --- | --- |
| DB 문서 | `nia_case_document` 3,581건 |
| DB text version | `nia_case_text/v1` |
| 임베딩 모델 | `BAAI/bge-m3`, 1,024차원 |
| 저장 임베딩 본문 | 질문 + 답변 + 추론 전체 |
| 운영 검색 질의 | 사용자 의도를 보존한 단일 질의 |
| 최초 검색 후보 | Top-40 |
| 리랭커 입력 후보 | 메타데이터 선별 최대 20건 |
| 리랭커 | `BAAI/bge-reranker-v2-m3` |
| 최종 결과 | Top-3 |

이번 평가 결과를 본 뒤 같은 골든셋으로 개선안을 비교할 수는 있지만, 최초 성능 측정 도중에 질의
생성 규칙·후보 수·메타데이터 규칙·모델을 바꾸지 않는다. 결과에 맞춰 골든셋 정답을 수정하는 것도
금지한다.

## 3. 제외 범위

- Evidence RAG 검색 및 Evidence 신뢰도
- 제품 검색·제품 추천 품질
- 루틴 생성 품질
- 최종 LLM 답변의 문장 품질
- 임베딩 재생성 또는 `nia_case_text/v2` 설계
- 복수 질의, RRF, BM25의 운영 적용
- Backend, DB 스키마, `config.yaml` 변경

복수 검색 방식이나 어휘 검색은 골든셋 후보를 넓게 발견하는 오프라인 도구로만 사용할 수 있다.
이는 현재 운영 파이프라인과 성능을 비교하기 위한 실험군이 아니다.

## 4. 기존 Anchor 평가와 새 평가의 역할

기존 `tests/agent/nia_case_eval_data/nia_case_retrieval_golden_24.jsonl`은 원본 Case를 먼저 고른 뒤 사용자형 질의를
작성한 known-item 회귀 테스트다. 특정 원본 Case ID를 다시 찾을 수 있는지 확인하는 데는
유효하지만, 의미상 동등한 Case를 오답 처리하므로 사용자 적합성 평가로 사용하지 않는다.

새 골든셋은 다음 원칙으로 별도 구축한다.

- 특정 Case를 먼저 고른 뒤 질의를 역으로 작성하지 않는다.
- 사용자 질의를 먼저 작성한다.
- 질의별 필요한 성분 **기능**, 허용 가능한 성분군, 주의사항을 먼저 고정한다.
- 전체 코퍼스에서 해당 사용자에게 유용한 복수 Case를 찾는다.
- 의미상 동등한 Case ID는 함께 정답 처리한다.

두 평가 결과는 합산하지 않는다.

| 평가셋 | 확인 목적 |
| --- | --- |
| 기존 Anchor 24 | 파이프라인 회귀 및 특정 Case 재현성 |
| 신규 Semantic Utility v1 | 실제 사용자 질의에 대한 Case 검색·선별·정렬 품질 |

## 5. 전체 코퍼스 1차 조사 결과

현재 `config.yaml`이 연결한 PostgreSQL에서 `nia_case_text/v1` 및 `BAAI/bge-m3` 조합이
3,581건임을 읽기 전용으로 확인했다. 적재 원본 JSONL의 집계도 동일했다.

| 대표 고민 | 문서 수 | 비율 |
| --- | ---: | ---: |
| 모공 | 1,532 | 42.8% |
| 미백(색소침착/기미/칙칙함) | 1,244 | 34.7% |
| 여드름/뾰루지 | 686 | 19.2% |
| 붉어짐(홍조) | 50 | 1.4% |
| 과각질/악건성 | 38 | 1.1% |
| 주름 | 25 | 0.7% |
| 민감성(트러블/자극감) | 4 | 0.1% |
| 피부처짐/탄력저하 | 2 | 0.1% |

추가 확인 사항:

- training 3,177건, validation 404건이다.
- 성별은 남성 1,912건, 여성 1,669건이다.
- 피부 타입은 복합성 1,839건, 중성 952건, 지성 706건, 건성 84건이다.
- `page_content`와 `embedding_text`가 다른 문서는 없다.
- 동일한 질문 원문을 가진 정확 중복 그룹이 44개이며, 총 88건이 중복 그룹에 속한다.
- `target_concern`이 `skin_concerns`에 그대로 포함되지 않은 문서가 3건 있다.

모공·미백·여드름이 전체의 약 96.7%이므로 전체 평균 하나만 제시하면 희소 고민의 실패가
가려진다. 반대로 8개 카테고리를 동일 비율로 평가하면 문서가 2~4건뿐인 희소 카테고리를
과대평가하고 known-item 평가에 가까워진다. 따라서 핵심 성능셋과 희소 고민 스트레스셋을 분리해
보고한다.

원본 `training`과 `validation`은 NIA 데이터 구축 당시의 출처 구분이며 이번 검색 평가의 독립
split으로 사용하지 않는다. 현재 시스템은 두 split의 문서를 모두 같은 DB에서 검색하고, 이
프로젝트에서 해당 문서로 BGE-M3를 추가 학습하지도 않았다. 따라서 두 split 모두 동일하게 후보와
정답이 될 수 있으며 `dataset_split`은 출처 추적용으로만 보존한다.

평가 오염을 막기 위한 분리는 원본 문서가 아니라 새로 만드는 사용자 질의에 적용한다. 먼저 10개
질의로 판정 기준을 calibration하고, 기준을 확정한 뒤 별도의 40개 질의를 동결해 최종 성능을
측정한다.

## 6. Semantic Utility v1 질의 구성

초기 v1은 총 50개 질의로 구성한다. 10개는 판정 기준 calibration에 사용하고 최종 headline
지표에서는 제외한다. 나머지 40개는 calibration 종료 뒤 동결하여 현재 고정 파이프라인의 최종
성능을 측정한다.

### 6.1 판정 기준 calibration 10개

검색 결과를 보기 전에 서로 다른 고민과 난이도를 가진 10개 질의의 성분 기능·허용 성분군·주의
기준을 작성한다. 이 단계에서는 다음을 확인한다.

- 사용자 상황 적합성과 추천 유용성 점수를 동일한 기준으로 반복 판정할 수 있는가?
- 특정 성분명 일치가 아니라 기능적으로 동등한 추천을 인정할 수 있는가?
- 등급 1과 2의 경계 및 추천 방향 충돌 기준이 충분히 명확한가?
- 후보 순위와 생성 방법을 가린 상태에서도 같은 판단을 내릴 수 있는가?

calibration 과정에서 판정표가 바뀌면 10개 질의를 모두 새 기준으로 다시 판정한다. 기준 확정 전
점수는 현재 RAG 성능으로 보고하지 않는다.

### 6.2 동결 평가셋 40개

calibration이 끝난 뒤 작성·동결한다. 구성은 다음과 같다.

#### 핵심·복합 성능 30개

| 유형 | 목표 질의 수 |
| --- | ---: |
| 모공 | 8 |
| 미백·색소침착 | 8 |
| 여드름·뾰루지 | 8 |
| 위 고민을 포함한 복합·혼동 질의 | 6 |

#### 희소 고민 스트레스 10개

전체 합격 점수를 좌우하게 하지 않고, 현재 DB가 답할 수 있는 범위와 실패 양상을 확인한다.

| 유형 | 목표 질의 수 |
| --- | ---: |
| 과각질·악건성 | 3 |
| 홍조 | 3 |
| 주름 | 2 |
| 민감성 | 1 |
| 피부처짐·탄력저하 | 1 |

희소 고민 10개는 동결 평가에는 포함하지만 핵심 30개의 전체 합격 점수와 합산하지 않는다.
카테고리별 결과와 실패 원인을 진단용으로 별도 보고한다.

### 6.3 질의 작성 규칙

- 특정 Case 문장을 바꿔 쓰지 않는다.
- 성분명을 질의에 먼저 넣지 않는다.
- 실제 사용자가 말할 법한 증상·부위·환경·생활 조건을 사용한다.
- 나이와 성별은 자연스럽게 필요한 질의에만 포함한다.
- 단순 고민, 프로필이 풍부한 고민, 복합 고민, 혼동하기 쉬운 고민을 섞는다.
- 질환 진단이 필요한 표현은 화장품 추천 문제와 구분하고 전문 진료가 필요한 조건을 판정 기준에
  기록한다.

## 7. 질의별 성분 추천 기준 작성

각 질의에 대해 검색 결과를 보기 전에 다음 기준을 먼저 고정한다.

| 필드 | 의미 |
| --- | --- |
| `primary_concerns` | 사용자가 해결하려는 주된 고민 |
| `secondary_concerns` | 함께 고려해야 하지만 주목적은 아닌 고민 |
| `required_functions` | 장벽 보완, 보습, 피지 조절처럼 필요한 기능 |
| `acceptable_ingredient_groups` | 같은 기능을 수행해 정답으로 허용할 성분군 |
| `caution_groups` | 자극 가능성, 병용 주의 등 반드시 고려할 내용 |
| `contradictions` | 해당 사용자에게 우선 추천하면 부적절한 방향 |

특정 성분 하나를 유일한 정답으로 지정하지 않는다. 예를 들어 장벽 보완이 필요한 질의에서는
세라마이드·콜레스테롤·지방산 조합과 다른 타당한 장벽 보완 접근을 기능 수준에서 판정한다.

이 기준은 현재 검색 결과와 분리해서 작성한다. 검색된 Case에 있는 성분을 보고 사후적으로 정답
성분을 추가하면 현재 모델에 유리한 순환 평가가 되기 때문이다.

## 8. 전체 DB 기반 판정 후보 풀 생성

질의마다 3,581건을 모두 독립적으로 수동 판정하는 것은 현실적이지 않다. 대신 전체 DB를 한 번
읽고 다음 후보를 합쳐 깊은 판정 풀을 만든다.

1. 현재 BGE-M3 dense 검색의 깊은 후보
2. 질문 원문 기반 어휘 후보
3. 관련 `target_concern` 및 `skin_concerns` 후보
4. 주 고민은 비슷하지만 추천 방향이 다른 hard negative
5. 나이·성별·환경만 같고 주 고민이 다른 hard negative
6. 판정된 문서와 동일하거나 거의 동일한 중복 Case

후보를 판정할 때는 현재 검색 순위와 후보 생성 방식을 가린다. 현재 Top-40에 나온 문서는 모두
판정 풀에 포함해 평가 결과에 미판정 문서가 섞이지 않게 한다.

희소 카테고리는 문서 수가 작으므로 관련 카테고리 전체를 검토한다. 모공·미백·여드름처럼 문서가
많은 카테고리는 pooled qrels 방식으로 판정하며, 이 경우 Recall은 보고서에서 `pooled Recall`로
명시한다.

### 8.1 calibration 후보 풀 생성 결과

10개 calibration 질의에 대해 다음 후보를 합쳐 내부 후보 파일과 블라인드 판정 파일을 생성했다.

- 현재 BGE-M3 dense Top-100
- 사용자 질문 어휘 Top-50
- 사전 추천 기준의 성분군 어휘 Top-50
- 관련 메타데이터의 어휘 Top-30 또는 희소 카테고리 전수
- dense Top-40에 들어온 다른 고민의 hard negative
- 선택된 질문과 정확히 같은 질문을 가진 중복 Case

| 항목 | 결과 |
| --- | ---: |
| calibration 질의 | 10개 |
| 중복 제거 후 전체 판정 후보 | 1,838건 |
| 질의당 평균 후보 | 183.8건 |
| 포함된 현재 dense Top-40 | 400/400건 |
| exact 질문 중복 표시 후보 | 82건 |
| dense hard negative 표시 후보 | 122건 |
| 점수가 0인 어휘 후보 | 0건 |

내부 후보 파일은 Case ID, 후보 출처, dense 순위와 점수를 보존한다. 블라인드 파일에는 안정적인
`review_key`, 사용자 프로필, 질문, 답변만 넣고 Case ID, 카테고리, 검색 순위, 후보 출처를
제거했다. 두 파일의 `review_key` 대응 관계가 10개 질의 모두 일치하는 것을 확인했다.

## 9. Case 관련도 판정

Case의 질문·메타데이터 적합성과 답변의 추천 유용성을 함께 보되, 두 점수를 별도로 기록한다.

### 9.1 사용자 상황 적합성

- 주된 피부 고민이 일치하는가?
- 증상과 피부 상태가 일치하는가?
- 부위·계절·환경 조건이 도움이 되는가?
- 나이·성별 차이가 실제 추천 방향을 바꾸는가?
- 사용자와 모순되는 주목적이 있는가?

### 9.2 추천 유용성

- 필요한 기능을 해결하는 성분군을 제시하는가?
- 사용자에게 적용 가능한 관리 방향인가?
- 핵심 주의사항을 누락하거나 반대되는 추천을 하지 않는가?
- 우연히 같은 성분명만 포함한 문서는 아닌가?

### 9.3 최종 관련도 등급

| 등급 | Enum | 판정 기준 |
| ---: | --- | --- |
| 3 | `HIGHLY_RELEVANT` | 사용자 상황과 추천 방향이 모두 잘 맞고 Top-3에 노출하기 적절함 |
| 2 | `RELEVANT` | 핵심 고민과 추천 기능이 맞으며 일부 부가 조건만 다름 |
| 1 | `SUPPORTIVE` | 일부 정보는 유용하지만 주된 사용자 상황 또는 추천 목적이 다름 |
| 0 | `NOT_RELEVANT` | 핵심 목적이 다르거나 추천 방향이 충돌함 |

`relevant_case_ids`는 등급 2와 3, `highly_relevant_case_ids`는 등급 3에서 파생한다. 등급 원본과
판정 이유도 함께 보존한다.

성별과 나이는 명시됐다는 이유만으로 hard filter로 사용하지 않는다. 실제 성분 추천과 주의사항을
바꾸는 조건일 때만 관련도에 반영한다.

### 9.4 calibration 층화 표본

전체 1,838건을 판정하기 전에 등급 경계가 반복 가능하도록 질의당 15건, 총 150건을 블라인드
표본으로 선정한다.

| 표본층 | 질의당 수 | 의미 |
| --- | ---: | --- |
| `dense_likely` | 5 | 현재 dense Top-40 안에서 여러 후보 신호가 겹친 문서 |
| `off_rank_alternative` | 5 | Top-40 밖이지만 성분·질문 어휘 등 보완 신호가 높은 문서 |
| `low_signal_contrast` | 5 | 선택 후보 중 질문·성분 신호가 낮아 등급 0·1 경계를 확인할 문서 |

표본층은 정답 라벨이 아니다. 예를 들어 `dense_likely`도 실제 판정에서 0점이 될 수 있고,
`off_rank_alternative`도 3점이 될 수 있다. 판정 파일에는 표본층을 숨기고 질문·답변·기본 프로필만
제공한다.

첫 판정 대상인 `calibration_dry_sensitive_winter_01` 15건의 결과는 다음과 같다.

| 관련도 등급 | 건수 |
| ---: | ---: |
| 3 — highly relevant | 1 |
| 2 — relevant | 5 |
| 1 — supportive | 4 |
| 0 — not relevant | 5 |

첫 판정에서 확인한 경계는 다음과 같다.

- 성별·연령이 달라도 볼의 계절성 건조·따가움과 장벽 관리가 맞으면 2~3점이 될 수 있다.
- 입술·관자놀이처럼 부위와 주 증상이 달라도 보습·진정 정보가 일부 유용하면 1점으로 남긴다.
- 모공이 주목적인 Case가 보습 성분을 언급하더라도 현재 질의의 relevant Case로 올리지 않는다.
- 따갑고 아픈 장벽 손상 부위에 산 성분의 반복 사용을 우선 권하면 추천 충돌로 0점 처리한다.
- 정확히 중복된 질문 두 쌍은 같은 등급을 유지하고 `duplicate_equivalent`를 기록했다.

## 10. 골든셋 신뢰성 확보

- 판정 이유를 고정된 reason code로 기록한다.
- 등급 1인 모든 경계 사례를 두 번째 순서에서 다시 검토한다.
- 등급 0과 2·3 중 일부를 섞고 순서를 바꿔 재판정한다.
- 정확·근접 중복 Case가 서로 모순된 등급을 받지 않았는지 검사한다.
- Case ID, 질의, 판정 결과의 중복과 누락을 단위 테스트로 막는다.
- 골든셋 버전, DB 문서 수, text version, embedding model, 생성 시각을 기록한다.
- 첫 성능 측정 전에 골든셋을 동결한다.
- 성능 결과를 확인한 뒤에는 명백한 데이터 오류만 별도 변경 이력과 함께 수정한다.

AI 기반 1차 판정은 일관된 대규모 검토에 사용하되 의료적으로 절대적인 정답이라고 표현하지
않는다. 최종 보고서에는 pooled qrels의 한계와 희소 카테고리의 표본 한계를 함께 기록한다.

## 11. 단계별 평가지표

### 11.1 임베딩 검색 Top-40

- `RelevantSuccess@40`: 등급 2 이상이 하나라도 있는 질의 비율
- `HighlyRelevantSuccess@40`: 등급 3이 하나라도 있는 질의 비율
- `PooledRecall@40`: 판정 풀의 relevant Case 중 Top-40 회수 비율
- `Precision@40`: Top-40 중 등급 2 이상 비율
- 카테고리 drift 및 중복 Case 비율

### 11.2 메타데이터 선별 Top-20

- `RelevantRetention@20`: Top-40의 relevant 후보 보존율
- `HighlyRelevantRetention@20`: Top-40의 highly relevant 후보 보존율
- 최고 등급 후보 제거 질의 수
- 직접 일치 후보 수 및 fallback 발생률

### 11.3 BGE 리랭커 Top-3

- `nDCG@3`: 0~3 등급을 반영하는 주 지표
- `Precision@3`: 등급 2 이상 비율
- `MRR@3`: 첫 등급 3 Case의 순위
- `HighlyRelevantSuccess@3`: 등급 3이 하나라도 있는 질의 비율
- Top-3 중복률
- 사용자 조건과 충돌하는 Case 노출률

전체 평균뿐 아니라 핵심 성능셋과 희소 스트레스셋, 고민 카테고리, 단순·복합 질의별 결과를
분리한다.

## 12. 초기 판정선

다음 값은 첫 실행 전에 확정할 초기 운영 판정선이다. 희소 스트레스셋은 표본과 DB 문서 수가 너무
작으므로 전체 합격 여부에 합산하지 않고 진단 결과로 제시한다.

| 핵심 성능셋 지표 | 초기 목표 |
| --- | ---: |
| `RelevantSuccess@40` | 90% 이상 |
| 최고 관련도 후보의 Top-20 보존 | 95% 이상 |
| `HighlyRelevantSuccess@3` | 80% 이상 |
| 평균 `nDCG@3` | 0.75 이상 |
| 명백한 추천 방향 충돌 Top-3 노출 | 0건 |

최종 지표는 동결 평가 40개에서만 계산한다. 질의 한 건이 2.5%를 차지하므로 소수점 점수만으로
결론 내리지 않고 실패 질의 수와 원인을 함께 제시한다. calibration 10개의 결과는 판정표 검증
기록으로만 남긴다. 기준선 조정이 필요하면 최초 결과와 분리된 후속 버전에서 변경한다.

완성도가 아니라 **현재 보유한 NIA Case 중 질의와 관련된 문서를 현재 RAG가 잘 찾아서 상위에

따라서 기존 `nia_case_semantic_golden_v1.jsonl`과 그 결과는 삭제하지 않고 초기 실험으로
보존하되, 새 골든셋의 정답 정의와 성능 수치에는 그대로 사용하지 않는다. 특히 외부 임상 기준에
의해 0점 처리된 Case는 새 기준으로 다시 판정한다.

#### 새 평가 질문

```text
사용자 질의
  → BGE-M3 dense Top-40이 관련 NIA Case를 확보했는가?
  → metadata Top-20 선별이 관련 Case를 보존했는가?
  → bge-reranker-v2-m3가 가장 직접적으로 관련된 Case를 Top-3에 배치했는가?
```

새 평가는 다음 질문을 다루지 않는다.

- 해당 Case 답변이 피부과 전문의의 최선 진료안인지
- 외부 논문·진료 지침과 완전히 일치하는지
- 이상적인 성분군과 주의사항을 모두 포함하는지
- NIA 원본 답변 자체의 의학적 품질이 충분한지

단, 사용자가 명시한 요청과 Case의 답변 방향이 반대인 경우는 검색 관련성에 직접 영향을 준다.
예를 들어 사용자가 현재 자극을 안정시키고 싶다고 했는데 Case가 활성 성분 추가를 주된 해결책으로
제안한다면, 이는 외부 의학 지식 때문이 아니라 문서가 사용자의 요청 방향과 충돌하기 때문에 낮게
판정한다.

#### 코퍼스 상대 관련도 등급

판정 입력은 사용자 질의와 NIA Case의 실제 질문·답변·메타데이터로 한정한다. 검색 순위와
후보 생성 출처는 계속 숨긴다.

| 등급 | 정의 |
| ---: | --- |
| 3 | 핵심 고민이 직접 일치하고, 요청 방향이 직접 일치하며, 피부 상태·증상·계절 등 핵심 맥락도 하나 이상 맞는다. |
| 2 | 핵심 고민과 요청 방향이 대체로 일치하지만 일부 맥락이 빠지거나, 인접 고민이더라도 같은 상태와 요청을 직접 해결한다. |
| 1 | 같은 고민 범주 또는 일부 증상·키워드만 관련되며, 현재 요청에 직접 활용하기는 어렵다. |
| 0 | 핵심 고민이 무관하거나 사용자가 명시한 현재 목표와 답변 방향이 직접 충돌한다. |

판정 우선순위는 다음과 같다.

```text
핵심 고민·증상·명시적 요청 방향
  > 민감성·건조·피부 타입·계절·부위
  > 나이·성별
```

나이와 성별은 질의에서 삭제하지 않는다. 다만 NIA Case 관련성의 필수 일치 조건으로 사용하지
않고, 유사한 후보 사이에서 맥락 적합도를 보조하는 약한 신호로만 사용한다.

#### 골든셋과 지표의 의미

- `relevant_case_ids`: 판정 후보 풀에서 2~3점을 받은 대표 관련 Case ID다.
- `highly_relevant_case_ids`: 판정 후보 풀에서 3점을 받은 직접 관련 Case ID다.
- `Pooled Recall@40`: 판정한 후보 풀의 관련 Case 중 dense Top-40이 회수한 비율이다. 전체
  3,581건의 완전 recall이라고 표현하지 않는다.
- `Precision@3`, `nDCG@3`: 실제 reranker Top-3 120건은 전부 판정하므로 직접 해석한다.
- `direction conflict@3`: 외부 의학 기준 위반 수가 아니라 명시적 사용자 요청과 반대되는 문서의
  Top-3 노출 수다.
- `corpus ceiling`: 피부과적으로 완벽한 답변의 존재 여부가 아니라, 현재 판정 풀에서 확인한 최고
  코퍼스 관련도다.

### 2026-09-26 OpenAI 운영 Intent 포함 1회 End-to-End 평가
