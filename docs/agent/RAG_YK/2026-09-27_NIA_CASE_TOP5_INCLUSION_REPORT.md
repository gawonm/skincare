# NIA Case Top-5 포함률 재평가

## 왜 다시 평가했는가

이 워크플로우의 Case reranker는 관련 사례를 다음 Claim 추출 단계에 **포함**시키는 역할이 크다. 따라서 1위와 3위의 순서를 따지는 nDCG보다, 실제 전달할 K건 안에 관련 사례가 있는지와 몇 건 있는지를 우선 보았다. 현재 운영 계약은 Top-3이므로 이번 Top-5는 **오프라인 가상 실험**이다.

## 비교 조건과 판정

- 기존 개발·회귀 질의 24건, NIA 사례 3,581건, 저장된 동일 후보 목록을 사용했다.
- `Dense40`: BGE-M3 후보 40건. `Hybrid40`: Dense 상위 36건 + 그 안에 없는 NIA **질문 필드** BM25 후보 4건. `Hybrid48`: Dense40 보존 + NIA 질문 필드 BM25 신규 후보 8건.
- 동일 `BAAI/bge-reranker-v2-m3`로 질의별 후보 합집합을 한 번씩 채점하고, 각 방식의 후보만 재정렬했다. 운영 reranker의 질문·답변 입력, 빈 `CareContext`의 부적합 필터, 정확한 질문·답변 중복 후순위 처리와 같은 규칙을 적용했다. 세 방식 모두 기존 Top-3 산출물과 24/24 질의에서 일치했다.
- 기존 v5 qrel 및 앞선 Codex 추가 판정 7건을 재사용했다. Top-5에 처음 등장한 질의–사례 쌍 34건은 현재 Codex 세션에서 질문과 답변을 읽고 같은 0~3 기준으로 판정했다. 검색 결과를 본 뒤 판정했으므로 블라인드 평가가 아니다.
- 등급 0: 핵심 목표와 무관하거나 관리 방향 충돌, 1: 주변 관련, 2: 핵심 고민과 요청에 관련, 3: 고민·맥락·요청이 직접 맞음. 이는 **NIA 코퍼스 내부 검색 관련도**이며 의학적 타당성 판정이 아니다.

- 등급 3 Hit는 각 방식에서 Top-3→Top-5로 2개 질의 증가했지만, 최종 값은 모두 19/24건이다.
- Dense40 대비 관련 사례 수@5가 늘어난 질의는 Hybrid40 1건, Hybrid48 2건이며 감소한 질의는 없었다. Hybrid48의 추가 이득은 `acne_03`의 관련 사례 1건과 `pigment_01`의 관련 사례 1건이다. Hybrid40은 `pigment_01`에서 1건 늘었다.
- 반대로 등급 3 **사례 개수**는 일부 질의에서 줄었다. 두 Hybrid 모두 `acne_04`에서 3→2건, Hybrid40은 `acne_08`과 `rare_dry_03`에서도 3→2건이다. `pigment_01`은 두 Hybrid에서 2→3건이다. `Hit`는 이 구성 차이를 드러내지 못한다.

## 지표를 읽는 법

| 지표 | 계산과 해석 |
| --- | --- |
| 후보 qrel Recall@40/48 | **판정한 풀 안의** 등급 2~3 사례 중 1차 후보에 들어온 비율. 전체 3,581건에서의 완전 Recall이 아니다. 후보 단계의 상한을 보여주지만 최종 전달 사례의 품질을 말하지 않는다. |
| Hit@K | 24개 질의 중 상위 K건에 등급 2~3 사례가 **한 건 이상** 포함된 질의의 비율. 한 건과 다섯 건을 똑같이 성공으로 세므로 포화될 수 있다. |
| 등급 3 Hit@K | 상위 K건에 등급 3 사례가 한 건 이상 포함된 질의의 비율. 강한 관련 사례 존재 여부를 본다. |
| 평균 관련 사례 수@K | 질의마다 상위 K건에 포함된 등급 2~3 사례 수를 세어 평균. 이 워크플로우의 ‘쓸 만한 사례를 충분히 담는가’에 Hit보다 민감하다. |
| P@K | K개 슬롯 중 등급 2~3 사례의 비율을 질의별로 계산해 평균. K가 늘면 사례 수가 증가해도 비율은 감소할 수 있어 K가 다른 조건을 단독으로 비교하지 않는다. |
| nDCG@K | 0~3 등급과 순위 할인을 함께 반영한다. 앞자리에 더 좋은 사례가 있는지 볼 때 유용하지만, **순서보다 포함이 중요한** 현재 질문의 주지표는 아니다. |

## 판단과 제한

Top-5로 넓히면 Hybrid의 Top-3 Hit 열세는 사라진다. 그러나 세 방식의 Hit@5와 등급 3 Hit@5는 같고, Hybrid48은 후보를 40→48건으로 늘려 평균 관련 사례 수@5를 3.667→3.750건만 올렸다. **현재 개발셋에서는 Hybrid나 Top-5가 성공 질의 수를 늘렸다는 근거가 없다.** Dense40을 그대로 유지하는 판단이 합리적이다. 관련 사례를 더 많이 담는 것이 목표라면 Hybrid48의 작은 이득은 후속 비교 대상으로 남긴다.

이번 실험은 저장된 후보와 빈 관리 맥락으로 재정렬한 것이다. BM25 인덱스·DB 조회의 종단 지연, 관리 필터가 실제로 활성화된 결과, Claim 추출 비용과 답변 품질은 측정하지 않았다. 현재 Case/Claim 입력 계약은 최대 3건이므로 Top-5가 실제 워크플로우 답변을 개선한다고 주장할 수 없다. 24개 질의는 반복 사용한 개발셋이며 복합 고민의 각 축이 모두 충족됐는지도 이 지표만으로는 알 수 없다.
