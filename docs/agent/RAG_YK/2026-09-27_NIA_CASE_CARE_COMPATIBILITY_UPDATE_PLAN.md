# NIA Case RAG 관리 조언 적합성 보완 계획

> 2026-09-27 진행 결과: [24건 재평가 보고서](2026-09-27_NIA_CASE_CARE_COMPATIBILITY_UPDATE_REPORT.md).
> 명시적 각질 제거 권고 필터와 CareContext 독립 판정은 완료했다.
> 구조화 조언의 OpenAI 오프라인 비교는 사용자 전송 승인 후 12건 실행했으며,
> 부적합 8건 중 1건만 찾아 운영 적용 기준을 통과하지 못했다.
> 기존 24건에 포함되지 않은 12건의 고정 후보 비교도 수행했다. 과거 프로젝트
> 평가에 쓰인 질의이므로 완전히 새로운 독립 검증과 전체 관리 적합성 판정은
> 다음 게이트로 남았다.
> 후속으로 [새 복합 질의 12건 점검](2026-09-27_NIA_CASE_FRESH_COMPOSITE_CHALLENGE_REPORT.md)을
> 실행했다. 필터 적용 뒤 10/12건에 Case가 남았고, 빈 결과 2건의 재검색은
> 출력은 복구했지만 부적합 조언을 남겨 운영에는 반영하지 않았다.

## 목표와 현재 기준

Case RAG는 사용자 고민과 관련된 NIA Q&A를 찾고, 선택한 사례에서 Claim을 추출해
Evidence 검증으로 넘긴다. 관련성이 높아도 지금 적용하기 어려운 관리 조언이라면
Claim 단계에 전달하기 전에 구분해야 한다. 이번 작업은 Agent의 Case 검색 경로와
`tests/agent/` 평가에 한정한다.

고정 비교 기준은 [24건 전체 평가](2026-09-27_NIA_CASE_CARE_CONTEXT_AI_JUDGED_REPORT.md)다.
Dense Top-40 후보, BGE 점수, 질의, 기존 관련성 qrel과 Codex가 추가한 6건의 관련성
판정을 그대로 사용한다. 현재 Precision@3은 0.819, nDCG@3은 0.748이며 Case 출력은
23/24건이다. 이 값은 반복 개선에 사용한 개발셋 결과다.

[관리 조언 검토](2026-09-27_NIA_CASE_CARE_APPLICABILITY_AI_REVIEW.md)에서
`evaluation_core_composite_01`의 현재 Top-3 모두 부위 제한 없는 각질 제거를
권하면서 필터를 통과한 것을 확인했다. 관련성 qrel과 현재 조언 적합성 판정은
서로 다른 평가값으로 유지한다.

## 1. 평가 기준 먼저 고정

1. 기존 24건의 기준·현재 Top-3와 변경 뒤 새로 노출될 후보를 대상으로 관리 조언
   적합성을 `부합 / 부적합 / 보류`로 판정한다. 권고 행위, 긍정·금지 표현, 적용 시점,
   적용 부위, 근거 원문을 함께 남긴다. 이미 판정한 8개 후보는 재사용한다.
2. 24개 사용자 질의의 `active / inactive / unknown`과
   `recovery / standard / unknown`을 원문에 근거해 따로 판정한다.
   저장된 OpenAI CareContext 예측을 정답으로 사용하지 않는다.
3. 후보를 추가 판정할 때 Case ID와 현재 순위를 가린 상태에서 답변과 질의를 읽고,
   판정 출처를 기록한다. Codex 판정은 사람 전문가의 임상 판정으로 표시하지 않는다.

**완료 조건:** Top-3 비교에 미판정 후보가 없고, 현재 조언 적합성과 CareContext의
판정 근거를 질의·후보별로 추적할 수 있다.

## 2. Case 필터의 놓침 수정

`agent/rag/retrieval/case_care_compatibility.py`에서 한 문장에 고위험 관리 단어와
권고 단어가 각각 존재하는지만 보는 방식을 점검한다. 먼저 확인된 놓침인
`각질 제거를 시행`, `이중 클렌징을 실시`, `주 1~2회 각질 제거`를 잡는다.
주간 횟수만으로는 제외하지 않고 각질 제거 등의 행위와 연결될 때만 권고로 본다.

같은 절 안의 금지, `회복 후` 같은 적용 시점, `T존만` 같은 적용 부위도 검사한다.
예를 들어 `각질 제거는 피하고 보습을 실시`는 제외 사유가 아니다.
`evaluation_core_composite_01`의 세 후보와 기존에 제외된 두 사례를 회귀 사례로
삼고, 금지·조건부 조언을 잘못 제외하는 반례도 포함한다.

필터는 현재 BGE 재정렬 뒤 Top-3를 정하기 전과 리랭커 실패 시 fallback에 동일하게
적용한다. 적합 후보가 없으면 현재 동작처럼 Case 결과를 보류하고, 부적합 후보로
Top-3를 채우지 않는다. 후보 순위 점수와 관련성 qrel은 바꾸지 않는다.

**완료 조건:** 확인된 누락 3건과 기존 제외 2건을 놓치지 않고, 금지·회복 후·부위
제한 사례를 잘못 제외하지 않는다. 필터와 fallback 단위 테스트가 통과한다.

## 3. 고정 후보 평가와 선택 기준

동일한 24개 질의와 저장된 Dense Top-40·BGE 점수로 `기준 V5 / 현재 / 수정안`을
비교한다. 새 OpenAI 응답이나 재검색 결과를 섞지 않는다.

| 축 | 지표 |
| --- | --- |
| 검색 관련성 | 관련 Case Hit@3, 등급 3 Hit@3, Precision@3, nDCG@3 |
| 현재 조언 적합성 | 부적합 Case Top-3 노출 수, 부합 후보 오제외 수, 보류 후보 수 |
| 서비스 범위 | Case 결과가 있는 질의 수, 적합 후보가 없어 보류한 질의 수 |
| 질의 해석 | CareContext 두 필드의 독립 판정 대비 오분류 사례 |

확인된 부적합 조언의 노출을 없애는 것이 첫 관문이다. 관련성 점수나 Case 출력 수가
떨어지면 수치를 숨기지 않고 어떤 후보가 바뀌었는지 함께 보고한다. 부적합 조언을
남기는 대신 관련성 점수만 높이는 수정은 채택하지 않는다.

**완료 조건:** 세 버전의 동일 조건 비교표, 질의별 교체 후보, 빈 결과 이유,
오제외 사례를 보고서에 제시한다.

## 4. 표현 규칙의 한계 확인

수정 후에도 부위·시점·부정 표현에서 놓침이나 오제외가 반복되면, 답변에서
`행위 / 권고 여부 / 시점 / 부위 / 원문 구절`을 구조화하는 판정을 **오프라인에서**
비교한다. 기존 채팅 모델을 이용한 구조화 판정의 정확도, 지연, 호출 비용을 측정한 뒤
런타임 적용 여부를 결정한다. 그 전에는 표현 목록을 무한히 늘리거나 새 모델 호출을
운영 경로에 추가하지 않는다.

## 5. 발표용 검증

개발에 사용한 24건과 별도로, 새 복합 질의 12건을 수정안 실행 전에 고정하고
관련성·관리 조언 적합성·CareContext를 같은 기준으로 판정한다. 기존에 사용한
종합 사례 3건은 오류 분석 사례로 제시한다. 신규 12건도 Codex가 판정한다면
판정 출처를 밝히고 사람 전문가 검증이라고 표현하지 않는다.

발표에는 `기준 V5 / 현재 / 수정안`의 개발셋 비교와 신규 질의 결과를 분리해 싣는다.
`기존 qrel의 요청 방향 충돌 4→0`은 관리 조언 전체의 안전성 지표로 사용하지 않는다.
표에는 표본 수, 후보 풀 고정 여부, 판정 출처, 빈 결과 처리 방식을 함께 적는다.
