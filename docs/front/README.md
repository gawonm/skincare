## AI 채팅 화면

### 기준 시안

피그마 파일 `2C2MK9s2UnKQMC3Hbm9O3X` 의 아래 세 화면을 따른다.

| 상태 | 노드 |
| --- | --- |
| 최초 진입 | `109:39` |
| 대화 중 | `109:76` |
| 응답 대기 | `109:118` |

같은 페이지의 `109:2`(제목 "성분 AI" + 추천 질문 카드 3개가 있는 최초 진입 변형)는 **따르지 않는다.**
`109:39` 를 최종안으로 정했고, 추천 질문 카드는 만들지 않는다.

### 응답 방식

`POST /chat` 은 SSE 가 아니라 완성된 단일 JSON 이다. 오류(`status: "error"`)도 200 으로 오며,
`retryable` 이 true 면 "다시 시도" 를 보여 준다. 재시도는 같은 `request_id` 로 다시 보낸다.
자세한 내용은 계약서 "실패했을 때" 절.

## 결정이 필요한 것 (구현 보류)

임의로 채우지 않고(CLAUDE.md 규칙 3) 아래는 시안·계약이 정해진 뒤에 붙인다.

| 항목 | 지금 상태 | 정해야 할 것 |
| --- | --- | --- |
| **"새 대화" 버튼** | 시안대로 헤더에 그리되 `disabled`, 동작 없음 | 대화 초기화 엔드포인트가 필요한지(계약서 "아직 안 정한 것" 2번). 화면만 비우면 Agent 는 이전 대화를 기억하는 채로 남아 사용자 기대와 어긋난다. 엔드포인트가 정해지면 `ChatHeader` 에 연결한다 |
| **`artifacts` 표시** | 응답 파싱(zod)만 하고 화면에는 `message` 만 보여 준다 | 후보 상품 목록 / 루틴 / 근거 답변을 어떻게 그릴지 시안 |
| **`citations` 표시** | 그리지 않음. `ChatSources`(시안의 "출처 · …" 줄)는 만들어 뒀으나 어디서도 쓰지 않는다 | 응답 `citations` 를 이 줄에 어떻게 연결할지 |
| **`partial` / `unresolved` 표시** | `message` 만 보여 준다. `ChatWarning`(시안의 안전 안내 박스)은 만들어 뒀으나 어디서도 쓰지 않는다 | 어느 필드를 안전 안내 박스에 보여 줄지 |
| **정지 버튼 의미** | 시안에 있어서 유지. 화면 대기만 끊고 서버는 그 턴을 계속 처리한다 | 정지 후 곧바로 다음 메시지를 보내면 서버가 어떻게 응답하는지(같은 방 동시 처리) 확인 |
| **전송 버튼 활성 모양** | 시안에는 비어 있을 때의 연회색 모양만 있어 입력 유무와 상관없이 같다 | 입력했을 때의 활성 모양 시안 |
| **인사말의 이름** | 시안은 "안녕하세요 {이름}님", 지금은 이름 없이 "안녕하세요" | `GET /auth/me` 로 이름을 불러오는 작업 |
| **`candidate_set_id` / `routine_version`** | 요청에 보내지 않는다 | 계약서 "아직 안 정한 것" 1번 |

## 시안과 다른 점 (의도적)

- 상태바(9:41)와 화면 모서리 둥근 틀은 기기 모형이라 그리지 않는다.
- 하단 탭은 시안대로 홈 / AI 채팅 / MY 3칸이다. 이전의 "스케줄"·"프로필" 은 없어졌다.
- Noto Sans KR 웹폰트는 로드하지 않는다(다른 화면도 시스템 폰트를 쓴다). 폰트를 맞추려면 별도 결정이 필요하다.
