# Claim·Evidence·상품·루틴 Agent 수정사항 및 파트별 확인 사항

- 작성일: 2026-09-23
- 대상 브랜치: `integration/claim-routine-evidence`
- 상태: Agent 수정 및 단위·통합 테스트 완료, `v5_2` 전체 Agent E2E 재실행 전
- 관련 파트: Agent, Backend, Frontend, Data

## 1. 문서 목적

초기 실행에서 발생한 루틴 규칙 검증 오류와 이후 점검에서 확인된 Claim, Evidence, 상품 검색,
루틴 배치 문제의 수정 내용을 공유한다. 또한 각 파트가 연동 전에 확인해야 할 항목과 완료 기준을
한곳에 정리한다.

이번 작업에서 `backend/`, `frontend/`, `data/scripts/`, DB 스키마는 수정하지 않았다. 아래의
파트별 항목은 Agent 변경을 연동하거나 `v5_2` 데이터를 배포할 때 각 담당자가 확인할 사항이다.

## 2. 최초 문제와 현재 결과

### 최초 문제

`max_frequency_per_week` 규칙에 주당 횟수가 없는 LLM 출력이 들어오면서 Pydantic 검증이 실패했고,
그래프 전체가 `graph_execution_failed`로 종료됐다.

```text
Value error, max_frequency_per_week 규칙에는 주당 횟수가 필요합니다.
```

동시에 다음 문제가 확인됐다.

- `3일간`이라는 루틴 기간과 `주 3회`라는 빈도 의미가 섞였다.
- `하루 두 번`, `아침저녁`이 주당 횟수 규칙으로 잘못 해석될 여지가 있었다.
- Evidence 질의에 사용자 원문 전체가 붙어 성분 효능 근거 검색의 초점이 흐려졌다.
- Evidence가 없어도 Case 문장의 성분명만으로 Claim이 승격될 수 있었다.
- 상품을 성분별로 반복 검색해 중복이 많았고, 고정 개수 제한 시 일부 성분의 상품이 사라질 수 있었다.
- 경고 수준의 루틴 규칙이 필수 규칙처럼 LLM 입력에 들어가 아침·저녁 중복 배치를 유발했다.
- 성분 Evidence와 완제품 효능 근거가 화면 문구에서 혼동될 수 있었다.

### 현재 결과

- 최초 Pydantic 오류는 재현되지 않는다.
- 같은 유형의 요청은 그래프 오류가 아니라 `partial` 결과와 제한 사유를 반환한다.
- 루틴 기간, 주간 횟수, 일일 사용 표현이 서로 다른 의미로 처리된다.
- Evidence가 없거나 미검수인 경우 근거 수준이 상품마다 명시된다.
- 상품은 추천 성분 전체를 기준으로 통합 검색한 뒤, 누락된 성분만 보완 검색한다.
- 마지막 `v5_1` 실제 E2E에서는 3일 모두 저녁 루틴만 생성됐고, 경고 규칙 때문에 아침·저녁이
  불필요하게 중복되는 현상이 사라졌다.

## 3. 확정된 정책

| 항목 | 확정 내용 |
| --- | --- |
| 횟수 해석 | 맥락 없이 `3회`, `4회`라고 나오면 각각 주 3회, 주 4회로 해석한다. |
| 일일 표현 | `하루 두 번`, `아침저녁`은 주당 14회로 환산하지 않는다. 부적합한 주간 빈도 규칙은 제외한다. |
| 기간과 빈도 | `3일간`은 루틴 기간이며 주 3회 규칙이 아니다. |
| 상품 표시 | `[성분 근거]`, `[제한 근거]`, `[미검수 근거]`, `[Claim 기반]` 중 하나를 사용한다. |
| 금지 문구 | Evidence가 없더라도 `임시 추천안`이라고 표시하지 않는다. |
| 완제품 근거 | 성분 Evidence를 완제품 자체의 임상·효능 근거처럼 표현하지 않는다. |
| 상품 개수 | 최종 상품을 5~6개로 고정 제한하지 않는다. 검색 결과가 있는 추천 성분은 최소 한 상품이 남도록 한다. |
| 의학적 제외 | 레티놀·산 성분 등을 코드의 고정 블랙리스트로 배제하지 않는다. LLM 판단과 구조화된 규칙·근거 상태를 사용한다. |
| 연관 근거 | 복합 소재 연구의 `ASSOCIATION`은 검색·표시할 수 있지만 단일 성분 직접 근거나 `SUPPORTED` 판정에는 쓰지 않는다. |

## 4. Agent 수정 내용

### 4.1 그래프 실행 순서

- 상품 후보가 준비된 뒤 루틴 계획을 생성하도록 실행 의존성을 고정했다.
- 루틴 생성 시점에 사용할 수 없는 상품을 참조하거나 후보가 뒤늦게 바뀌는 문제를 막았다.

### 4.2 Case Claim 검증

- 성분명만 있는 문장은 효능·주의 Claim으로 승격하지 않는다.
- 영문 Case 성분명과 한국어 원문 인용이 같은 표준 성분을 가리키면 동치로 검증한다.
- 근거가 없는 성분 추천은 Claim 기반 후보로 유지하되 Evidence가 있는 것처럼 표시하지 않는다.

### 4.3 Evidence 질의와 근거 등급

- 사용자 원문 전체를 붙이던 질의를 성분별 목적 질의로 축약했다.

```text
변경 전: 미네랄솔트: 30대 남성, 요즘 환절기여서 ... 3일간 스킨케어 루틴 짜줘
변경 후: 미네랄솔트: 피지 여드름 관련 효능 및 주의사항
```

- Evidence 상태와 검수 수준을 다음 네 단계로 분리했다.

| 내부 기준 | 사용자 표시 | 의미 |
| --- | --- | --- |
| 검증된 Evidence | `[성분 근거]` | 대상 성분과 Claim을 직접 뒷받침하는 검증 근거가 있다. |
| 제한적 Evidence | `[제한 근거]` | 범위·대상·주장에 제한이 있어 그대로 일반화할 수 없다. |
| 미검수 Evidence | `[미검수 근거]` | 검색됐지만 아직 검수 완료 근거가 아니다. |
| Evidence 없음 | `[Claim 기반]` | Case Claim을 기반으로 추천했으며 검증 Evidence는 없다. |

### 4.4 상품 통합 검색

- 추천 성분 ID 전체를 한 번에 넘기는 통합 검색을 우선한다.
- 통합 검색 결과에서 상품이 없는 성분만 성분별 보완 검색한다.
- 중복 상품을 합치면서도 검색 결과가 있는 각 추천 성분의 대표 상품은 남긴다.
- 검색 단계의 후보 풀 크기와 사용자에게 보여 주는 최종 개수는 별도 개념으로 처리한다.

### 4.5 루틴 규칙과 배치

- 기간 일수와 주간 사용 횟수를 별도 필드·검증 흐름으로 분리했다.
- 필수 규칙만 LLM 초안 생성에 전달한다.
- 경고 규칙은 최종 계획과 검증 결과에는 남기지만, 슬롯 수를 강제로 늘리지 않는다.
- 같은 시간대의 단계 순서는 상대 순서를 보존한 채 `1..N`으로 정규화한다.
- 프롬프트에 상품 목록은 후보 풀이고, 기간과 시간대는 배치 범위이며, 경고는 반복 배치 명령이
  아니라는 점을 명시했다.

### 4.6 검색어와 성분 별칭

- Case 검색 질의에서 고민어가 중복으로 들어가던 문제를 제거했다.
- 알로에, 안디로바, 양고추냉이, 키틴, 미네랄솔트의 한글·영문 별칭을 보강했다.
- CLI 성분 조회는 정규화·영문 후보보다 정확한 한국어 표준명 일치를 우선한다.
- 이 우선순위는 여러 후보가 `OR` 조건으로 조회될 때 표준 성분 행이 다른 후보에 가려지는 문제를 막는다.

## 5. 검증 결과

### 자동 테스트

다음 테스트 묶음은 최종 Agent 변경 기준으로 통과했다.

```powershell
uv run --cache-dir .uv-cache pytest tests/agent tests/unit/test_ingredient_alias_mapper.py -q
```


변경 파일 대상 Ruff 검사도 통과했다.

### 실제 Agent 실행

- 최초 질문 유형의 E2E 실행이 `graph_execution_failed`가 아닌 `partial`로 완료됐다.
- `partial` 사유는 검증된 Evidence 부족과 일부 성분의 상품 부족이며 그래프 실행 실패가 아니다.
- 마지막 `v5_1` 실행에서는 3일 저녁 루틴이 생성됐고 불필요한 아침·저녁 복제는 없었다.

### `v5_2` Evidence 직접 검색

로컬 `config.yaml`의 대상 DB를 `skincare_reference_20260923_v5_2`로 전환한 뒤 실제 2-Layer
Evidence 검색기를 직접 호출했다. OpenAI를 사용하는 전체 Agent E2E는 아직 재실행하지 않았다.

| 성분 | `v5_1` | `v5_2` | 판정 |
| --- | ---: | ---: | --- |
| 키틴 | 0건 | 2건 | 검색 성공, 두 건 모두 미검수 연관 근거 |
| 알로에베라잎즙가루 | 0건 | 0건 | 직접 근거 없음 |
| 안디로바씨오일 | 0건 | 0건 | 직접 근거 없음 |
| 고추냉이뿌리추출물 | 0건 | 0건 | 직접 근거 없음 |
| 미네랄솔트 | 0건 | 0건 | 직접 근거 없음 |

키틴 검색 조건과 결과는 다음과 같다.

```text
질의: 키틴: 피지 여드름 관련 효능 및 주의사항
ingredient_id: c4399298-58ae-4df1-8f6b-eeaae7a98ce3
상태: success
Evidence: 2건
청크: 2건
리랭커: BAAI/bge-reranker-v2-m3
```

| Evidence ID | 문헌 제목 | 연결 대상 | 검수 상태 |
| --- | --- | --- | --- |
| `25c818b3-2668-4ec8-9a04-a7765c727c6d` | Chitin-glucan, a natural cell scaffold for skin moisturization and rejuvenation. | 키틴 + 베타글루칸 | 미검수 |
| `bf01ae73-1b82-4676-b576-9df840f20839` | Fungal chitin-glucan scaffold for managing diabetic xerosis of the feet in menopausal women. | 키틴 + 베타글루칸 | 미검수 |

두 문헌은 키틴 단독 및 피지·여드름 직접 근거가 아니다. `키틴-글루칸` 복합 소재의
`ASSOCIATION`이므로 Agent 출력에서는 `[미검수 근거]` 또는 제한 사유와 함께 다뤄야 하며,
키틴 단독 Claim을 `SUPPORTED`로 승격하면 안 된다.

## 7. 파트별 확인 항목

### Agent

- [x] 잘못된 `max_frequency_per_week` 출력이 그래프 전체 실패로 이어지지 않도록 검증했다.
- [x] 기간, 주간 횟수, 일일 표현을 분리했다.
- [x] 필수 규칙과 경고 규칙을 루틴 초안 생성 단계에서 분리했다.
- [x] Claim 검증과 Evidence 등급을 분리했다.
- [x] 상품 통합 검색과 누락 성분 보완 검색을 적용했다.
- [x] 단위·통합 테스트 235건을 통과했다.
- [ ] `v5_2`에서 OpenAI를 포함한 전체 Agent E2E를 1회 실행한다.
- [ ] E2E 결과에서 키틴 연관 근거가 단독 성분 확정 근거로 표시되지 않는지 확인한다.
- [ ] 미해결 성분명이나 LLM 오탈자가 별칭으로 과도하게 확정되지 않는지 관찰한다.

### Backend

- [ ] 운영 DB를 `v5_1`에서 `skincare_reference_20260923_v5_2`로 전환할지 확정한다.
- [ ] 운영 조립 코드가 legacy `rag_chunk` 검색이 아니라 `evidence_chunk` 기반 2-Layer 검색기를
  주입하는지 확인한다.
- [ ] Evidence 응답에서 `target_ids`, `scope=ASSOCIATION`, 문서 상태, 검수 상태를 누락하지 않는다.
- [ ] 검수 상태가 `NULL` 또는 미완료이면 검증 근거로 승격하지 않고 미검수로 전달한다.
- [ ] 다중 성분 상품 검색 요청을 단일 성분 반복 호출로 다시 분해하지 않는다.
- [ ] API나 서비스에서 상품 배열을 임의로 5~6개로 잘라 성분 커버리지를 없애지 않는다.
- [ ] Agent의 `partial`을 서버 오류로 바꾸지 않고, 답변과 제한 사유가 있는 정상 완료 상태로 전달한다.
- [ ] 운영 성분 조회에서도 정확한 한국어 표준명 일치가 정규화 후보보다 우선하는지 확인한다.
- [ ] `v5_2` 연결 상태에서 Backend 기동·DB 연동 테스트를 수행한다.

### Frontend

- [ ] 상품 근거 배지를 `[성분 근거]`, `[제한 근거]`, `[미검수 근거]`, `[Claim 기반]`으로 표시한다.
- [ ] Evidence가 없을 때 `임시 추천안`이라는 문구를 만들거나 덧붙이지 않는다.
- [ ] `partial` 응답도 답변 본문과 루틴을 표시하고, 제한 사유를 별도 안내한다.
- [ ] `no_evidence`, `missing_information`을 화면 전체 오류가 아닌 항목별 안내로 처리한다.
- [ ] 상품 개수를 5~6개로 가정하지 않고 가변 길이 목록으로 렌더링한다.
- [ ] 아침·저녁 슬롯이 항상 모두 존재한다고 가정하지 않는다.
- [ ] 루틴 단계는 서버가 준 시간대별 순서대로 표시한다.
- [ ] 성분 연관 근거를 완제품 자체의 효능 검증 문구나 배지로 표현하지 않는다.

### Data

- [ ] `v5_2` 덤프와 SHA-256 파일을 배포·복원 담당자에게 함께 전달한다.
- [ ] DB명 `skincare_reference_20260923_v5_2`와 Alembic revision `9f4c2a7d8e61`을 확인한다.
- [ ] 키틴 문헌 2건이 키틴과 베타글루칸 모두에 연결되고 `ASSOCIATION`으로 유지되는지 확인한다.
- [ ] 두 문헌의 검수 상태가 현재 미검수임을 배포 메모에 명시한다.
- [ ] 키틴-글루칸 문헌을 키틴 단독 또는 키토산 직접 근거로 재분류하지 않는다.
- [ ] 나머지 네 성분의 0건 결과를 유사명·유도체·성분군 근거로 임의 보충하지 않는다.
- [ ] `evidence_document=128`, `evidence_chunk=8487`, `evidence_chunk_ingredient=8508`을 복원 후 대조한다.
- [ ] 고아 링크, 임베딩 누락, 동일 Evidence ID의 scope·target 충돌이 없는지 검사한다.
- [ ] 재현에 필요한 원본·수동 검수 입력 파일이 Git 비추적 대상이라면 별도 인수인계 묶음에 포함한다.

## 8. 파트 간 완료 기준

| 순서 | 담당 | 확인 내용 | 완료 조건 |
| ---: | --- | --- | --- |
| 1 | Data | `v5_2` 덤프·체크섬·revision·건수 제공 | 복원 DB의 건수와 체크섬이 인수인계 값과 일치 |
| 2 | Backend | `v5_2` 연결 및 2-Layer Evidence 검색기 조립 | 키틴 질의에서 2건과 association 메타데이터 반환 |
| 3 | Agent | 전체 E2E 실행 | 그래프 오류 없이 완료되고 키틴 근거가 과장되지 않음 |
| 4 | Frontend | 배지·partial·가변 상품·루틴 슬롯 표시 | 네 근거 배지와 제한 사유가 의미대로 렌더링됨 |

## 9. 남은 위험과 미확정 사항

- 로컬만 `v5_2`이고 운영 설정은 아직 `v5_1`이다. 운영 전환 시점은 Backend·Data가 함께 확정해야 한다.
- `v5_2`에서 OpenAI를 포함한 전체 E2E는 아직 실행하지 않았다. 실행 시 API 비용과 외부 데이터 전송이 발생한다.
- 키틴 2건은 검색 성능 확인에는 유효하지만 피지·여드름 또는 키틴 단독 효능의 직접 근거는 아니다.
- 나머지 네 성분에 Evidence가 없는 것은 현재 데이터 범위의 결과다. 검색 성공을 만들기 위해 느슨한
  성분군 확장을 추가하면 근거가 과장될 수 있다.
- LLM의 성분 선택과 루틴 배치는 구조 검증을 통과해도 도메인 판단 품질이 달라질 수 있으므로 실제
  질문 세트로 계속 관찰해야 한다.
